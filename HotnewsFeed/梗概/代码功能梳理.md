# HotnewsFeed 代码功能梳理

> 阅读顺序：先看「功能实现图谱.png」，再按本文档的 1→5层往下读。  
> 核心原则：**Agent 负责判断与调度，MCP 负责跨进程工具调用，tools 负责真实业务，MySQL/Redis/Milvus 负责持久化。**

---

## 0. 项目最终提供的功能

1. **当前热点新闻**：多源采集后聚类、计算热度、核验可信度。
2. **最新新闻**：按板块与关键词采集，时间倒序返回。
3. **账户发布查询**：查询指定账户最近发布的新闻或作品。
4. **实时多 Agent 链路**：Coordinator 经 A2A 委派 Collector / Processor / Publisher / Video / AccountMonitor Agent，Agent 再经 MCP 或业务服务调用工具。
5. **离线新闻库**：每天 06:00 抓取五个板块，原文写 MySQL，向量写 Milvus，精确问题缓存写 Redis，只保留 3 天。
6. **离线 RAG 查询**：Redis 精确命中；未命中时 Milvus 召回 Top3 ID，再回 MySQL 取原文。
7. **每日分板块简报**：科技、财经、体育、娱乐、国际分别生成简报并推送。
8. **B 站账户持续监控**：轮询 UP 主空间，BV 号去重，新视频提取字幕/音频转写，生成摘要后通知。

---

# 一、四条功能链路是怎么跑的

## 1. 在线「最新新闻」

1. `main.py` 接收用户输入。
2. `intent_agent.py` 使用 `HotnewsFeedPrompts.intent_prompt()` 识别为 `latest_news`。
3. `CoordinatorAgent.route()` 从语句提取板块和关键词，例如“足球”映射为“体育 + 足球”。
4. Coordinator 经 `a2a.protocol.delegate()` 向 `CollectorAgent` 发送 `collect_news`。
5. Collector 经 `mcp_access.collect_news()` 连接 Collect MCP `:8004`。
6. Collect MCP 执行 `tools.collect.collect_news()`，抓 RSS / HN / Google News / Bing News，然后过滤、去重、排序。
7. `PipelineResult(task_type="latest_news")` 逐层返回，`main.py` 格式化展示。
8. 结果完成后 Coordinator 询问是否生成简报；确认后交给 PublisherAgent。

## 2. 在线「当前热点」

前 6 步与最新新闻相同，但采集后继续：

1. Coordinator 向 ProcessorAgent 委派 `cluster_events`：Embedding 相似度聚类，Embedding 失败则用 TF 词频向量。
2. 委派 `score_heat`：结合资讯数、来源数和时效性得分。
3. 委派 `verify_events`：LLM 给出“可信 / 存疑 / 证据不足”；LLM 失败则使用条数与来源数规则。
4. 返回 `List[HotEvent]`，按热度倒序取 TopN。

## 3. 离线新闻与每日简报

1. `offline_news_scheduler.py` 每天 06:00 触发 `OfflineNewsService.ingest()`。
2. `crawler.py` 按五个板块调用在线采集器，并用 `_ArticleParser` 抓文章正文。
3. `MySQLNewsStore.upsert()` 用 `news_uid` 去重，写标题、摘要、正文和过期时间。
4. `MilvusNewsIndex` 每批 10 条生成 1024 维 Embedding，只存 MySQL ID 和向量。
5. 删除 MySQL/Milvus 中超过 3 天的记录，并清空旧查询缓存。
6. `briefing.py` 从 MySQL 按板块取今日数据，调 Publish MCP 生成 5 份简报。
7. 离线查询时，`OfflineNewsService.query()` 先查 Redis，miss 时用 Milvus 查 ID，最后去 MySQL 取最多 3 条原文。

## 4. B 站账户新视频监控

1. `account_monitor_scheduler.py` 默认每 30 分钟调用 `AccountMonitorService.check_all()`。
2. `tools.bilibili` 通过 `yt-dlp + cookie_file` 读取最近视频，返回 `AccountPost`。
3. `AccountMonitorStore.existing_ids()` 用 `(platform, post_id/BV号)` 判断是否新发布。
4. 首次运行默认只建立基线，不把历史视频推送给用户。
5. 新视频经 A2A 委派给 VideoAgent，VideoAgent 调 Video MCP `:8007`。
6. `tools.video` 先选中文字幕；没有字幕时用 `yt-dlp` 取音频、`imageio-ffmpeg` 转 16kHz 单声道 WAV、DashScope ASR 转写。
7. LLM 从转写中生成摘要和关键词，保存到 `account_posts`。
8. 新发布经 Publish MCP 发送飞书/邮件/Webhook，或写入本地 Markdown。

# 二、第 1 层：入口、配置与日志

## `main.py`

**作用**：对外测试主程序，提供循环对话，输入 `exit` 退出。

- `main()`：打印帮助、检查 MCP 状态、创建 CoordinatorAgent，进入 `input()` 循环。
- `handle_command()`：处理 `/hotspot`、`/latest`、`/account`、`/offline`、`/monitor`、`/status`。
- `format_result()` / `_format_item()`：把 `HotEvent / NewsItem / AccountPost` 转为终端文本。
- `check_mcp_servers()`：通过 `mcp_list_tools()` 探测 4 台 MCP。
- `query_offline_news()`：正式暴露的 Python 离线查询函数。
- `_extract_offline_query()`：识别“离线查询……”，避免误送到在线 Agent。

## `offline_main.py`

**作用**：只调试离线库的轻量对话窗口。

- `format_rows()`：显示 Redis 或 Milvus+MySQL 来源链路。
- `main()`：循环查询，最多显示 3 条。

## `config.py`

**核心类 `Config`**：统一读 `config.ini`，其他代码不再硬编码地址与密钥。

- `llm/mysql/redis/milvus`：返回各服务连接参数。
- `offline_news`：返回板块、保留天数、06:00 调度和每日简报配置。
- `account_monitor`：返回轮询间隔、Cookie、ASR、通知通道。
- `publish/rss_sources/accounts`：返回推送、RSS 和监控账户配置。

## `config.ini`

**作用**：运行配置，包含 LLM、MySQL、Redis、Milvus、Embedding、推送、RSS、离线新闻和账户监控参数。  
**注意**：B 站使用 `cookie_file`，不应在文件中写明文账号密码。

## `create_logger.py`

- `setup_logger()`：创建控制台 INFO + 文件 DEBUG 双通道 Logger。
- 全局 `logger`：所有 Agent、MCP 网关、工具和调度器共用。

# 三、第 2 层：Agent 与意图识别

## `agents/intent_agent.py`

- `intent_agent(user_input)`：调用 `intent_prompt` 和 qwen-plus，返回 `(intents, user_queries, follow_up_message)`。
- 意图为 `hotspot_query / latest_news / account_follow / account_monitor / out_of_scope`。
- 负责判断“做什么”，不直接抓新闻。

## `agents/coordinator_agent.py`

**核心类 `CoordinatorAgent(A2AServer)`**：系统的调度大脑。

- `route()`：调意图 Agent，再路由到热点/最新/账户任务。
- `_guess_module()` / `_guess_keyword()`：把“足球”等主题映射到板块和关键词。
- `_guess_account()`：抽取 @账户和平台。
- `_delegate()`：通过 A2A 调用功能 Agent，解码统一 `{ok,result,error}`。
- `run_hotspot()`：Collector 采集 → Processor 聚类/评分/核验。
- `run_latest()`：只调 Collector，按时间返回。
- `run_account_follow()`：委派 Collector 查账户发布。
- `handoff_briefing()`：任务完成后询问用户，确认后委派 Publisher。
- `handle_message()`：Coordinator 自身的 A2A 入口。

## `agents/collector_agent.py`

**`CollectorAgent(A2AServer)`**：采集功能 Agent。

- `collect_news()`：通过 Collect MCP 调多源新闻。
- `fetch_account_posts()`：通过 Collect MCP 查账户发布。
- `handle_message()`：按 `task_type` 在两种采集能力中路由。

## `agents/processor_agent.py`

**`ProcessorAgent(A2AServer)`**：数据加工 Agent。

- `cluster_events()`：调 Process MCP 聚类。
- `score_heat()`：调 Process MCP 计算热度。
- `verify_events()`：调 Process MCP 核验事件。

## `agents/publisher_agent.py`

**`PublisherAgent(A2AServer)`**：输出 Agent。

- `optimize_output()`：统一输出整理入口；当前为轻量原样返回。
- `publish_briefing()`：调 Publish MCP 生成并推送简报。

## `agents/video_agent.py`

**`VideoAgent(A2AServer)`**：视频内容 Agent，A2A 端口 `8008`。

- `extract()`：调 Video MCP，返回 `VideoContent`。
- `handle_message()`：接收账户监控服务的 `extract_video_content` 委派。

## `agents/account_monitor_agent.py`

**`AccountMonitorAgent(A2AServer)`**：持续账户监控的下游业务 Agent，A2A 端口 `8009`。

- `register_monitor`：把主页地址注册到 MySQL，并可立即做一次基线检查。
- `check_monitors`：检查所有启用账户，触发增量去重、视频转写和通知。
- `monitor_status`：返回监控数量、最后检查时间和错误。
- `stop_monitor`：停用监控但保留历史视频和转写。
- Coordinator 只抽取参数并 A2A 分发，不直接访问监控数据库。

## `agents/__init__.py`

- `_LAZY`：类名到模块的映射。
- `__getattr__()`：惰性导入 Agent，避免包导入时把 LLM 和网络客户端全部加载。

# 四、第 3 层：A2A 与 MCP

## `a2a/protocol.py`

- 使用官方 `python_a2a`，不自定义协议类。
- `send_task()`：把 `task_type/params/from_agent` 放入 `Message.metadata`。
- `parse_task()`：功能 Agent 取回任务参数。
- `encode_result()`：把 dataclass 递归转 dict，生成统一 JSON。
- `AgentNetwork`：管理 Collector `8001`、Processor `8002`、Publisher `8003`、Video `8008`、AccountMonitor `8009`。
- `delegate()`：字符串目标走 HTTP A2A，Agent 实例则走同进程演示。
- `ask_user_confirm()`：控制台简报确认入口。

## `a2a/__init__.py`

导出 A2A 适配函数，让其他模块用稳定的包入口导入。

## `mcp_servers/mcp_access.py`

**整个 Agent 层通往工具层的统一网关。**

- `MCP_URLS`：Collect `8004`、Process `8005`、Publish `8006`、Video `8007`。
- `_no_proxy_http_client()`：`trust_env=False`，避免 Windows 系统代理拦截 localhost。
- `mcp_call_tool()`：`streamablehttp_client → ClientSession.initialize → call_tool`。
- `_parse_payload()`：兼容 FastMCP 把列表拆成多个 TextContent 的返回方式。
- `sync_call()`：把同步 Agent 方法桥接到 async MCP 函数。
- 八个业务网关：采集、账户发布、聚类、热度、核验、发布、视频提取等。
- 所有网关都是“MCP 优先，服务不可达则进程内直调 tools”。

## 四个 MCP Server 文件

| 文件 | FastMCP | 端口 | 注册工具 |
|---|---|---:|---|
| `mcp_servers/mcp_collect_server.py` | `NewsCollect` | 8004 | `collect_news`, `fetch_account_posts` |
| `mcp_servers/mcp_process_server.py` | `NewsProcess` | 8005 | `cluster_events`, `score_heat`, `verify_events` |
| `mcp_servers/mcp_publish_server.py` | `NewsPublish` | 8006 | `publish_briefing` |
| `mcp_servers/mcp_video_server.py` | `VideoContent` | 8007 | `extract_video_content` |

四个文件逻辑相同：创建 `FastMCP` → 用 `register_to()` 挂载工具 → `run(streamable-http)`。  
`mcp_servers/__init__.py` 只负责包说明。

# 五、第 4 层：流水线、数据结构与工具

## `task_pipelines/schemas.py`

- `HotEvent`：热点事件。
- `NewsItem`：单条新闻。
- `AccountPost`：账户发布。
- `PipelineResult`：三种上游任务的统一返回外壳。
- `dto_from_dict()`：把 MCP/A2A JSON 恢复成 dataclass。
- `no_real_items()`：识别空结果或全模拟数据。

## 三个 `task_pipelines`

- `task_pipelines/hotspot_query_pipeline.py`：采集 → 聚类 → 热度 → 核验 → `PipelineResult`。
- `task_pipelines/latest_news_pipeline.py`：采集 → 时间倒序 → `PipelineResult`。
- `task_pipelines/account_follow_pipeline.py`：账户采集 → since 增量过滤 → `PipelineResult`。
- `task_pipelines/__init__.py`：包入口说明。

## `tools/registry.py`

- `ToolDefinition`：保存工具名、描述和 handler。
- `COLLECT_TOOLS / PROCESS_TOOLS / PUBLISH_TOOLS / VIDEO_TOOLS`：按 MCP Server 分组。
- `register_to()`：循环调用 `server.tool(...)(handler)` 完成注册。

## `tools/collect.py`

**新闻采集的真实实现。**

- `_fetch()`：统一 User-Agent 和 timeout 下载网页。
- `_parse_feed()`：用 ElementTree 同时解 RSS 2.0 和 Atom。
- `_fetch_rss()` / `_fetch_hn()` / `_fetch_news_search()`：三类真实源。
- `_expand_terms()`：扩展关键词别名。
- `_matches()`：检查标题与摘要。
- `collect_news()`：并发采集、since 过滤、板块/关键词过滤、标题指纹去重、时间排序。
- `fetch_account_posts()`：Bilibili 走专用适配器，普通 RSS 账户走 feed 解析。

## `tools/process.py`

- `EventCluster`：事件簇，保存成员 ID、中心向量、来源和时间范围。
- `_embed_texts()`：DashScope Embedding。
- `_tf_vectors()`：Embedding 不可用时的本地词频向量。
- `_cosine()`：余弦相似度。
- `cluster_events()`：贪心单遍聚类，相似度超阈值就并入已有簇。
- `_heat_score()` / `score_heat()`：使用文章数、来源数和时效加分。
- `verify_events()`：LLM 核验，失败用 `_heuristic_credibility()`。

## `tools/publish.py`

- `PublishResult`：简报 ID、各通道成功状态和错误。
- `_generate_briefing()`：优先 LLM，失败使用 `_format_markdown()`。
- `_push_feishu / _push_email / _push_webhook`：真实推送。
- `_write_local()`：`web_ui` 通道写 `output/briefings`。
- `publish_briefing()`：并发执行配置通道，单通道失败不中断其他通道。

## `tools/bilibili.py`

- `extract_space_uid()`：从 UID/空间 URL 中提取数字 UID。
- `_ydl_options()`：组装 Cookie、Referer、超时、禁用系统代理等 yt-dlp 配置。
- `fetch_bilibili_space_videos()`：读取最近视频，转成 `AccountPost`；352/412 时明确提示 Cookie，不伪造数据。

## `tools/video.py`

- `VideoContent`：视频 ID、标题、作者、转写、摘要、关键词和内容来源。
- `_pick_subtitle()`：中文人工字幕优先，其次自动字幕。
- `_subtitle_text()`：兼容 B 站 JSON 字幕、JSON3 和 VTT。
- `_download_wav()`：下载最佳音频，用内置 FFmpeg 转 16kHz 单声道 WAV。
- `_transcribe()`：DashScope `Recognition` 语音识别。
- `_summarize()`：LLM 生成 JSON 摘要与关键词。
- `extract_video_content()`：按“字幕→ASR→简介降级”的顺序编排。

## `tools/__init__.py`

工具包标识；不在包导入时启动服务或执行网络请求。

# 六、第 5 层：离线库、账户监控、调度和输出

## `offline_news/crawler.py`

- `CrawledNews`：离线入库 DTO，`news_uid` 用 SHA-256 保证去重。
- `_ArticleParser(HTMLParser)`：优先抽取 `<article>/<main>` 中段落。
- `_fetch_article()`：下载单篇新闻正文。
- `crawl_module()`：采集单板块且并发补正文。
- `crawl_all_modules()`：并发抓五板块，按 `news_uid` 去重。

## `offline_news/stores.py`

### `MySQLNewsStore`

- 自动创建 `news_rag` 和 `offline_news`表。
- `upsert()` 重复新闻更新，不重复插入。
- `active_for_index()` 让上次中断的 Milvus 索引可自动补齐。
- `expired_ids/delete_expired()` 清理 3 天前数据。
- `fetch_by_ids()` 按 Milvus 召回顺序返回 MySQL 原文。

### `RedisQueryCache`

- `normalize_query()` 统一小写和空格。
- SHA-256 问题作为 Redis key，TTL 默认 6 小时。
- Redis 失效时按 miss 处理，不使主查询中断。

### `MilvusNewsIndex`

- 自动创建数据库/集合，COSINE 度量。
- Embedding 按每批最多 10 条提交。
- `upsert()` 只保存 MySQL ID 和 vector。
- `search_ids()` 最多召回 3 个 ID。

## `offline_news/service.py`

**`OfflineNewsService`**：离线系统总编排类。

- `initialize()`：初始化 MySQL/Milvus。
- `ingest()`：采集 → MySQL → 过期清理 → Milvus 补齐 → Redis 失效 → 每日简报。
- `query()`：Redis → Milvus → MySQL，最多 3 条。

## `offline_news/briefing.py`

- `generate_daily_briefings()`：循环五个板块，从 MySQL 取今日 TopN，转 `NewsItem`，调 Publish MCP。
- 单板块失败不中断其他板块。

## `offline_news/__init__.py`

导出 `OfflineNewsService`，为 `main.py` 和调度器提供简洁入口。

## `account_monitor/store.py`

**`AccountMonitorStore`**：

- 创建 `monitored_accounts`：账户、空间、最后检查、最后错误。
- 创建 `account_posts`：BV 号、转写、摘要、关键词、是否通知。
- `existing_ids()`：批量判断 BV 号是否已见。
- `save_posts()`：幂等 upsert。
- `delete_mock_posts()`：保证持续监控库不会保存模拟数据。

## `account_monitor/service.py`

**`AccountMonitorService`**：

- `initialize()`：创表、注册 `config.ini [accounts]` 账户。
- `_extract_video()`：优先 A2A VideoAgent，Agent 未起则直调 Video MCP。
- `check_account()`：拉取 → 拒绝 mock → BV 去重 → 内容提取 → 保存 → 推送。
- `check_all()`：遍历所有配置账户。
- `status()`：供 `/monitor status` 展示。

## `account_monitor/__init__.py`

导出 `AccountMonitorService`。

## 两个调度器

- `scheduler/offline_news_scheduler.py`：`--init`、`--run-once`、`--briefing-only`；常驻时每天 06:00。
- `scheduler/account_monitor_scheduler.py`：`--init`、`--run-once`；常驻时默认每 30 分钟。
- `scheduler/__init__.py`：调度包标识。

# 八、第三方类/库在项目中的职责

| 类/库 | 在本项目中的用途 |
|---|---|
| `python_a2a.A2AServer` | 把功能 Agent 暴露为 A2A HTTP 服务 |
| `AgentCard / AgentSkill` | 声明 Agent 身份、职责和能力 |
| `AgentNetwork` | Coordinator/监控服务查找并调用其他 Agent |
| `FastMCP` | 创建工具服务并注册 handler |
| `streamablehttp_client` | Agent 端真实连接 MCP HTTP 端点 |
| `ClientSession` | MCP 初始化握手、列工具和调工具 |
| `ChatOpenAI` | 通过 DashScope OpenAI 兼容接口调 qwen-plus |
| `ChatPromptTemplate` | 给意图、核验、简报提供可填充模板 |
| `OpenAI.embeddings` | text-embedding-v3 新闻聚类和离线向量化 |
| `pymysql` | MySQL 原文、监控状态与去重 |
| `redis.Redis` | 离线问题精确缓存 |
