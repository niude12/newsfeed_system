HotnewsFeed 全项目代码级实现详解
=================================

说明
----
这份文档不是只说“某个文件负责什么”，而是从当前源码最底层开始，逐个解释：
1. 类或函数的完整签名；
2. 每个参数是什么、默认值是什么；
3. 返回什么 Python 类型、内部字段是什么；
4. 函数内部按什么顺序执行；
5. 调用了哪个下一层函数；
6. 成功、空结果和异常时分别返回什么；
7. 该返回值怎样被上层继续使用。

阅读顺序严格按“底层数据和工具 → 存储 → 协议 → Agent → 调度 → main 入口”展开。


第一层：配置、日志和公共数据对象
================================

一、config.py：所有模块读取 config.ini 的唯一入口
-------------------------------------------------

模块常量：PROJECT_ROOT
  值：Path(__file__).resolve().parent。
  含义：config.py 所在的 HotnewsFeed 绝对目录。日志、输出目录、Cookie 和临时目录的相对路径最终都基于它转换成绝对路径。

函数：_clean(value)
  参数：value 是 configparser 读取到的 str 或 None。
  返回：str。
  内部逻辑：None 返回空字符串；否则 strip 去空白，再去掉两侧单/双引号。

类：Config
  __init__(self, config_path=None)
    config_path 不传时使用 PROJECT_ROOT/config.ini。创建 self._parser 并用 UTF-8 读取；读取失败抛 FileNotFoundError。

  get(self, section, key, default=None)
    section/key 指定配置项。返回 _clean 后的字符串；节或键不存在返回 default。

  属性 llm
    返回 dict：base_url、api_key、model_name，来源 [llm]。

  属性 mysql
    返回可传给 pymysql.connect 的 dict：host、port(int，默认3306)、user、password、database、charset(默认utf8mb4)。

  属性 redis
    返回 host、port、password、db、key_prefix、cache_ttl_seconds；空密码转 None，数值转 int。

  属性 milvus
    返回 uri、database_name、collection_name、dimension(int，默认1024)。

  属性 offline_news
    返回 modules 列表、per_module_limit、retention_days、query_top_k、schedule_hour/minute、fetch_article_content、article_concurrency、daily_briefing_enabled、daily_briefing_top_n、daily_briefing_channels。query_top_k 被 min(3,配置值) 强制上限3；多个 true/yes/on 字符串转换成 bool。

  属性 temperature
    返回 float，默认0.1。

  属性 log_file
    返回绝对路径 str。普通相对路径拼到 PROJECT_ROOT；类似 os.path.join(...) 的表达式占位会回退 PROJECT_ROOT/logs/app.log。

  _section_items(self, section)
    返回该节全部清洗后键值 dict；节不存在返回 {}。

  属性 embedding_model
    返回 [embedding].model_name，默认 text-embedding-v3。

  属性 publish
    返回飞书/Webhook/SMTP/output_dir 配置；smtp_port 转 int；output_dir 转绝对路径。

  属性 rss_sources
    返回 Dict[str,List[str]]；每个模块配置值按逗号拆 URL。

  属性 accounts
    返回 [accounts] 的账户到抓取地址映射。

  属性 account_monitor
    返回 interval_minutes、latest_limit、notify_on_first_run、process_video_content、notify_channels、bilibili_cookie、cookie_file、asr_model、temp_dir。Cookie和临时目录相对路径转绝对路径。

直接运行 config.py：只做配置自测，不打印 api_key。


二、create_logger.py：统一双通道日志
----------------------------------

setup_logger(name, log_file=None) -> logging.Logger
  name 是日志器名；log_file 不传则 Config().log_file。
  内部依次创建目录、getLogger、总级别 DEBUG、propagate=False、创建格式器、INFO控制台Handler、DEBUG UTF-8追加文件Handler。只有 logger.handlers 为空才挂载，防止重复输出。模块最后创建全局 logger=setup_logger('HotnewsFeed')。


三、task_pipelines/schemas.py：跨层数据契约
-----------------------------------------

HotEvent dataclass
  必填：event_id、module、title、heat_score、credibility、sources。
  可选：article_count=0、first_seen_at=""、latest_at=""、summary=""。

NewsItem dataclass
  必填：news_id、module、title、source、published_at、url；summary=""。

AccountPost dataclass
  必填：post_id、account、platform；title/content/published_at/url 默认空。

PipelineResult dataclass
  必填：task_type、items；queried_at=""、elapsed_ms=0、error=None。

dto_from_dict(cls, d)
  d 已是 cls 实例则原样返回；否则只保留 cls.__dataclass_fields__ 中存在的键后 cls(**dict)。多余字段会忽略，但缺少无默认值的必填字段仍会 TypeError，并非真正“自动补齐全部字段”。

no_real_items(items) -> bool
  空列表或全部 title 以【模拟】开头时 True，否则 False。


第二层：在线新闻采集工具
========================

四、tools/collect.py：RSS、HN、搜索源和账户发布
-----------------------------------------------

DEFAULT_RSS_FEEDS 保存板块源；DEFAULT_SOURCES=[rss,hn]；MODULE_TERMS 用于综合来源模块过滤；KEYWORD_ALIASES 将足球扩展为 football/soccer/英超等；SOURCE_HANDLERS 将来源名映射到异步函数。

_now_iso() -> str
  返回本地当前时间 YYYY-MM-DDTHH:MM:SS。

_clean_text(value) -> str
  None→""，非str先str；移除BOM；非法Unicode用U+FFFD替换，避免MCP UTF-8序列化失败。

_fetch(url: str, timeout: int=10) -> bytes
  创建带浏览器UA的 urllib Request，urlopen 后 read。网络异常向调用者抛。

_parse_date(value: Optional[str]) -> str
  先按RFC822解析，再按ISO前19位解析；成功返回ISO秒级时间，失败空字符串。

_local_name(tag: str) -> str
  去掉 XML {namespace} 前缀。

_first_field(fields: dict, *names)
  返回首个不为None的XML Element，否则None。

_expand_terms(terms: Optional[List[str]]) -> List[str]
  同义词展开、小写、保持顺序去重。

_matches(item: NewsItem, terms: List[str]) -> bool
  title+summary 转小写，包含任一term即True。

_is_general_source(item: NewsItem) -> bool
  source 属于综合Feed或 Hacker/Google/Bing News 时True，需要模块过滤。

_parse_feed(xml_bytes, module, source) -> List[NewsItem]
  ElementTree解析RSS2/Atom；找channel/item或feed/entry；取标题、link、摘要、时间；空标题丢弃；摘要截200字；url或标题做MD5前8位生成rss-ID；未知时间保持空；返回NewsItem列表。非法XML向上抛。

async _fetch_rss(module, since, limit) -> List[NewsItem]
  配置源优先，否则默认源。普通URL在线程抓取并解析；search:前缀调用关键词搜索。逐源串行处理，单源失败只warning。since在本函数不使用，由collect_news统一过滤。

async _fetch_hn(module, since, limit) -> List[NewsItem]
  抓topstories IDs并截limit；每个ID用gather并发抓JSON；仅保留story和有标题项；构造hn-ID、时间、URL和得分摘要。单条失败跳过。

async _fetch_news_search(keywords, limit, module) -> List[NewsItem]
  关键词空格拼接并URL编码；先Google News RSS，失败/空再Bing；Google标题剥来源后缀；首个成功源返回前limit；全失败返回[]。

_mock_news(module,count=3) -> List[NewsItem]
  创建标题带【模拟】的演示数据，只用于所有真实来源原始结果为0。

async _fetch_sources(module,since,limit,sources) -> List[NewsItem]
  为已知source创建handler协程，gather(return_exceptions=True)并发；未知源和异常源跳过；成功结果展平。

async collect_news(module, keywords=None, sources=None, since=None, limit=50) -> List[NewsItem]
  1. sources为空用rss+hn；
  2. 并发抓各来源；
  3. 有keywords时额外用keywords直接搜Google/Bing，补充窄主题召回；
  4. 保存raw_count；
  5. since可解析时删除无时间或早于下限项；非法since忽略；
  6. 有keywords时扩同义词并严格过滤；无keywords时只对综合来源按MODULE_TERMS过滤，专用RSS保留；
  7. published_at倒序；标题移除非单词字符、转小写、截40位做去重指纹；
  8. 截limit；
  9. 结果空且raw_count=0才返回模拟；raw_count>0但不相关则如实返回[]。

_resolve_account_feed(account, platform) -> Optional[str]
  去@后查conf.accounts，再查原account；account本身是HTTP URL则返回；否则None。platform当前未用于映射。

_mock_posts(account,platform,count=3) -> List[AccountPost]
  返回缺配置时的模拟发布。

async fetch_account_posts(account,platform,since=None,limit=50) -> List[AccountPost]
  解析真实地址；没有则模拟。B站平台委托fetch_bilibili_space_videos。其它平台把地址当RSS，NewsItem转AccountPost，post-ID为标题/url MD5前8位。普通RSS异常返回模拟；B站分支在try之前，异常会真实抛出供监控层记录。


第三层：B站和视频内容
====================

五、tools/bilibili.py
--------------------

extract_space_uid(value: str) -> str
  纯数字原样返回；否则正则提取space.bilibili.com/UID；失败ValueError。

_ydl_options(limit: int) -> dict
  返回yt_dlp静默、extract_flat、playlistend、skip_download、Referer、禁系统代理、20秒超时、2次重试配置。bilibili_cookie放Header；cookie_file先验证存在再设置，否则FileNotFoundError。

async fetch_bilibili_space_videos(account,space_url,since=None,limit=20) -> List[AccountPost]
  解析UID并规范化URL；内部extract闭包在线程执行yt_dlp.extract_info(download=False)。异常包装RuntimeError并提示Cookie。since转timestamp cutoff；遍历entries，过滤旧时间；提取bvid/title/description/url/UTC时间，构造AccountPost并返回前limit。这里只取列表和简介，不提取字幕。


六、tools/video.py
-----------------

VideoContent dataclass
  video_id/title/author/published_at/transcript/summary必填；keywords=[]、source_url=""、content_source="metadata"。

_ydl_options(download=False,output="") -> dict
  返回完整视频元数据/下载配置，含Cookie、禁系统代理、超时重试；output非空设置outtmpl。

_pick_subtitle(info: dict) -> dict
  在subtitles和automatic_captions中按zh-CN、zh-Hans、zh、ai-zh、danmaku优先，取候选最后一条；无中文取任意轨道；没有返回{}。

_subtitle_text(track: dict) -> str
  规范化//URL，抓UTF-8文本。支持B站JSON body[].content、events[].segs[].utf8，以及VTT/SRT文本；后者过滤时间轴/编号/WEBVTT/NOTE并去HTML标签。

_download_wav(video_url,directory) -> str
  imageio_ffmpeg定位ffmpeg；yt_dlp下载bestaudio；后处理为16000Hz单声道WAV；目录找第一份.wav，无文件RuntimeError。

_transcribe(wav_path) -> str
  设置dashscope.api_key；Recognition使用配置模型、wav、16000；状态非200抛错；get_sentence统一成list；拼接text/sentence。

_summarize(title,transcript,description) -> tuple[str,List[str]]
  内容优先transcript>description>title；全部空返回("",[])。ChatOpenAI要求严格summary/keywords JSON，只发送前12000字。解析失败返回原响应前500字和空关键词。

async extract_video_content(video_url,platform="bilibili",prefer_subtitle=True) -> VideoContent
  检查平台；在线程yt_dlp取元数据；优先选字幕并解析；无字幕创建临时目录下载音频+ASR，失败只warning；调用LLM摘要；转UTC发布时间；返回VideoContent。transcript是完整字幕/ASR文本，summary才是精简内容。


第四层：加工和输出
==================

七、tools/process.py
-------------------

EventCluster dataclass
  必填cluster_id/title/member_ids/centroid；可选created_at/module/sources/first_seen_at/latest_at。

_embed_texts(texts) -> Optional[List[List[float]]]
  OpenAI兼容embeddings.create；按index排序。异常返回None触发TF降级。

_normalize(text) -> str：压缩空白。

_tokenize(text) -> set：英文数字单词+单个中文字符+相邻中文二元组。

_tf_vectors(texts) -> List[List[float]]
  全批次共享词表，生成词频向量并L2归一化。

_cosine(a,b) -> float
  空、维度不同或零向量返回0；否则点积除范数。

_merge_uniq(lst,values) -> List[str]
  副本中追加非空不重复值。

async cluster_events(news_items,threshold=0.8) -> List[EventCluster]
  空输入[]。标题+摘要向量化；失败TF。单遍扫描每条新闻，与全部簇质心求余弦；最佳值达阈值则并入并更新ID、来源、均值质心、最长代表标题和时间范围，否则创建evt-UUID前8位新簇。

_heat_score(cluster,time_window_hours) -> float
  30基础 + min(成员,30)*1.5 + min(来源,8)*4 + 时效奖励(1h/6h/24h/72h分别20/12/6/2)，封顶100。time_window_hours本身不缩放公式。

async score_heat(clusters,time_window_hours=24) -> List[HotEvent]
  最新时间超窗的簇跳过；时间未知保留。转换HotEvent，credibility先设待核验，按分数倒序。

_heuristic_credibility(event) -> str
  文章>=3且来源>=3→可信；文章>=2→存疑；否则证据不足。

async verify_events(events) -> List[HotEvent]
  空列表原样。事件核心字段转JSON，verify_prompt|llm在线程调用；解析event_id到credibility。失败使用启发式。原地修改每个event.credibility并返回。

PublishResult dataclass：briefing_id、channels必填，error=""。

_write_local(output_dir,briefing_id,text) -> str：创建目录，写briefing-ID.md，返回路径。

async publish_briefing(task_result,channels=None,template="default") -> PublishResult

第六层：离线与监控业务服务

十一、offline_news/crawler.py
----------------------------

CrawledNews dataclass：news_uid/module/title/source/url/summary/content必填，published_at=""。
to_dict(self) -> Dict：dataclasses.asdict。

_ArticleParser.__init__：depth=0、parts=[]。

十二、offline_news/service.py
----------------------------

OfflineNewsService.__init__
  创建mysql/redis/milvus对象和_initialized=False。

initialize() -> None
  MySQL建表、Milvus连接建集合、置True。

async ingest() -> Dict[str,object]
  initialize→crawl_all_modules→MySQL upsert→查过期ID先删Milvus→删MySQL→active_for_index全量重建/补齐向量→清Redis→可选每日简报。返回crawled/indexed/deleted/elapsed_ms/briefings。stored变量当前未参与返回。

十三、offline_news/briefing.py
-----------------------------

async generate_daily_briefings() -> Dict[str,dict]
  遍历模块；MySQL取今日topN；空则skipped。行转NewsItem，摘要不足用content前300字；包装offline_daily_模块 PipelineResult；调用publish网关。单板块异常不会影响其它板块。


十四、account_monitor/service.py
------------------------------

AccountMonitorService.__init__：self.store=AccountMonitorStore。

initialize() -> None

1. 在线最新：main→Coordinator.route→intent_agent→槽位抽取→A2A Collector :8001→MCP网关→MCP :8004→tools.collect→NewsItem→A2A JSON→DTO→PipelineResult→format_result。

当前源码真实边界
================

1. Coordinator的user_queries只记录日志，参数来自本地别名扫描。
2. A2A子Agent未启动时Coordinator报错；MCP未启动时功能Agent会进程内降级tools.*。
3. B站Cookie提供登录态，浏览器运行时无需打开；Cookie过期需重导。
4. notify_on_first_run=false时首次基线不做视频转写，所以早期行可能仅URL/简介。
5. transcript是完整文本，summary是精简文本，增强后的content写summary。
6. 关键词零命中返回空，不拿无关新闻补数量。
7. Redis是完全相同查询缓存；Milvus只存向量和MySQL ID；原文在MySQL。
8. PublisherAgent.optimize_output和三个summarize提示模板尚未真正接入。
